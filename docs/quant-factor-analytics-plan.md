## 1. 建设判断

下一阶段应形成一个完整的因子研究闭环：

**研究假设 → 因子定义与血缘 → 有界裂变 → 样本内筛选 → 冻结候选 → 样本外验证 → 组合回放 → 收益与风险归因 → 新一轮研究提案。**

NGFI 已有因子图、模型、优化器、成交账本和实验存储。最有价值的增量是让平台能够回答：

1. 这个因子表达什么假设，由哪些数据和算子构成？
2. 新因子与已有因子有什么差别，是独立信息还是同一信号的重复表达？
3. 预测能力主要来自行业、规模等已知暴露，还是控制这些暴露后仍有增量？
4. 加入组合以后，增量是否被换手、容量、交易限制和费用消耗？
5. 结论在哪些市场状态失效，下一次应检验什么具体假设？

首期优先级是**资产契约与评估治理、归因正确性、受控裂变**。大规模搜索和高性能执行在这些能力稳定后推进。LocalQuant 的算子与数据库方法适合作为设计参考；NGFI 继续使用原生计算和 ResearchWorkspace，不引入 LocalQuant 运行时依赖。

## 2. LocalQuant 已核实的资产与边界

### 2.1 数据库与运行时是两套不同口径

固定提交的 `localquant/predefined/factors/factors.db` 实际统计：

| 表 | 行数 | 作用 |
|---|---:|---|
| `factors` | 773 | 因子来源、公式、结构指纹、分类 |
| `operators` | 91 | 算子名称及分类字典 |
| `factor_ops` | 3,286 | 因子使用哪些算子 |
| `factor_dag` | 11,881 | 按深度记录父子标签 |
| `factor_pool` | 773 | 统一名称、原始名称与重复映射 |

来源分布为 Alpha101 82、Alpha158 174、Alpha191 114、Alpha360 336、talib 67；计算域分类为时序 710、截面 63。库内不同 fingerprint 数量为 773。文档记载从 797 个去重到 773 个；本次核实当前库数量，没有重跑原始构建过程。

`localquant/fre_runtime/config/operators.json` 另有 **105 项注册定义**，版本为 `2026-03-30`，记录输入、参数、缺失策略及各引擎实现状态。91 条数据库字典记录与 105 项运行时定义不能直接互换，也不能全部描述为“105 个已验证可运行算子”。

### 2.2 最值得吸收的四个方法

| 方法 | 源码证据 | 在 NGFI 中的用途 |
|---|---|---|
| 遍历表达式图提取依赖 | `op_sum.py` 的 `_collect_ops`、`_collect_edges`、`analyze_factor` | 查询输入血缘、算子依赖、受影响因子和中间节点 |
| 结构指纹判重 | `op_sum.py::_serialize_op`、`factor_pool.py::build_factor_pool` | 在计算前识别同一表达式，避免重复试验与计算 |
| 计算域和经济标签分层 | `factor_pool.py::classify_factor`、`_semantic_tag` | 组织因子检索、家族和研究覆盖 |
| 显式算子契约 | `contracts/operator_registry.py`、`contracts/factor_ir.py` | 由元数据驱动校验、解释、资源估算与候选生成 |

这些方法能让因子成为可管理的资产。但需要调整其语义：

- `_serialize_op` 按类型、参数和有序子节点构造结构指纹；这支持结构去重，不是完整的代数等价证明。
- `FactorDB.similar` 使用算子集合 Jaccard。两个因子都用 `SMA` 和 `DIV`，不能据此判断收益相关或信息重复；窗口、字段、顺序都可能不同。
- `_semantic_tag` 将含相关/协方差的某些表达式映射为流动性类，这是启发式标签。NGFI 应区分“作者假设的经济含义”和“实测风格暴露”。
- `factor_dag` 保存父子标签与 depth，缺少稳定节点身份、输入端口和完整参数；不能直接用它重建可执行 DAG。
- 分类序号根据组内排序生成。类似 `ts_mom_001` 适合做某版目录的别名，永久身份应由内容及版本决定。
- 库内 `ts_tec` 有 333 项，Alpha360 有 336 项，数量包含大量窗口/滞后展开；773 不是 773 个独立经济假设。
- 数据库文档中的核心输入是 OHLCV/amount；不能把预留的基本面、质量、成长分类视为已有 PIT 基本面因子库。

### 2.3 对“归因”能力的核实

LocalQuant 主包中可直接确认的是**结构依赖、分类和相似度分析**。本次没有在主包发现完整的因子收益归因或自动裂变评估流水线。

仓库包含两处需要区分的相关代码：

1. `qlib-main/qlib/backtest/profit_attribution.py::brinson_pa`：按行业或分箱构造组合/基准权重和组收益，计算配置、选股、交互贡献。它位于附带 Qlib，文件明确标注维护不足，依赖 Qlib 数据和持仓接口，并有 forward-fill、成交价与报告收益不一致等说明。本次未发现它被 LocalQuant 主包调用。
2. `validation/nmw/backtest_utilts_new.py::plot_monthly_attribution`：按月和持有资产汇总日收益并绘图。这是资产收益展示，不能替代风格归因或复利连接。

因此 NGFI 可以借鉴 Brinson 分解方法，但需要使用自己的实际持仓、时间口径和成交账本重新实现适配。不能把该附带模块描述成已接通的 LocalQuant 因子归因引擎。

### 2.4 算子语义要按实际入口核对

一个典型例子：LocalQuant 通用 `WindowedStddev` 文档描述样本标准差，而 FRE 编译器 `_op_std` 明确调用 `_population_std`；NGFI 原生 `STD` 使用 `ddof=0`。迁移时应比较实际入口的实现及 fixture，不能凭相同名称或一段通用文档判断等价。

FRE 编译器会将后处理引用的节点物化为输出；这本身不代表中性化已执行。注册表中的 `implemented/planned/not_applicable`、编译能力和端到端处理能力应分别核实。

上游根许可证为 Apache-2.0，附带 Qlib 文件标注 MIT。未来若实际移植代码或表达式，按具体来源补充 notices、来源提交与修改说明；本轮按 NGFI 原生契约实现，没有复制上游运行时代码。

## 4. 因子资产与算子数据库

### 4.1 权威数据仍在 ResearchWorkspace

采用“**不可变定义与研究产物 + 可重建关系索引**”：

- 内置算子与种子定义随代码版本管理。
- 自定义因子、研究候选、评估和归因结果由 ResearchWorkspace 管理。
- SQLite 仅存检索索引和指向 artifact 的引用；损坏后可由校验过的 manifest/artifact 重建。
- 因子面板不逐单元塞进 SQLite；首版沿用有界 artifact，规模化时再使用分区列式文件。
- catalog 只读查询不隐式创建研究 case。所有持久写入经过应用层的 revision 和锁。
- 跨 case 因子复用保存明确版本引用，不依赖可变“最新目录”。索引按 workspace 权限隔离。

初期索引很小可以先使用内存投影；SQLite 的引入服务于反向依赖、家族查询和评估检索，不建立第二套实验台账。

### 4.2 最小对象与索引关系

| 对象/索引 | 关键内容 |
|---|---|
| `OperatorDefinition` | `opId/version`、类别、输入输出类型/单位规则、参数、缺失策略、时间依赖、资源估算、实现身份 |
| `FactorVersion` | DAG、输入、输出、后处理及顺序、表达式 hash、语义版本、数据要求、hypothesis/evidence 引用 |
| `FactorAlias` | 人类名称、来源库/提交、原名称、目标版本；允许多个来源映射同一语义定义 |
| `factor_nodes/edges` | `factorVersionId/nodeId/opVersion/params`，边记录上游节点及 `inputIndex` |
| `factor_operator_usage` | 从 DAG 派生的反向依赖，支持算子变更影响分析 |
| `FactorFamily/Lineage` | 根因子、父版本、变换类型/参数、生成器版本、研究批次、创建原因 |
| `EvaluationRegistration` | 数据、样本切分、候选全集/预算、指标、方向规则、成本、随机种子 |
| `FactorEvaluation` | 因子版本、注册、fold/horizon/universe、指标及 coverage、状态、产物引用 |
| `AttributionRun` | 归因类型/版本、模型/组合/数据引用、时间口径、贡献、缺失和核对误差 |

不要让一个 `factor_name` 同时承担展示名、源码身份、经济类别和试验身份。建议区分：

- `expressionHash`：规范 DAG、参数、变换顺序、算子版本和语义策略的内容身份；忽略节点展示名称和描述文案。
- `factorVersionId`：表达式与语义输入绑定、来源及版本身份。
- `evaluationId`：进一步绑定数据、样本、执行环境和评估规则。

表达式改变产生新版本；只修订标签可以产生单独的元数据记录。保留上游 alias 与重复映射，不删除有来源价值的记录。

### 4.3 算子契约比算子数量更重要

每个算子明确：

1. **形状与类型**：标量、数值面板、布尔面板、分类面板、风险暴露集合。
2. **单位**：价格、股数、金额、收益率、无量纲；加减需兼容，价格比率可得到无量纲，`log(price)` 需显式归一化。
3. **时间**：只读取历史；滚动窗口、`minPeriods`、延迟与可得时间传播规则。`SMA(DELAY(x,5),20)` 需要 24 个前置交易日，不能只取两个窗口的最大值。
4. **截面**：计算 universe、eligible mask、行业 vintage、权重和最小样本；不能混用今天的成员或分类。
5. **数值**：`ddof`、rank 并列规则、除零阈值、常数截面、NaN/Inf、溢出及 clipping。
6. **状态**：EMA 等递归算子的初始化、缺失处理、warm-up、checkpoint 身份；不能伪称有限窗口即可完整复算。

`availableAt` 由实际依赖的可见观察传播；包含行业/风险输入的变换同样接受截止时点检查。财报持续有效值可按已核实版本规则 carry-forward，但不能反向填充历史未知值，也不能混淆取数时间和首次公开时间。

首批新增建议：`DELTA`、`TS_RANK`、`CORRELATION`、`COVARIANCE`、`DECAY_LINEAR`、`TS_QUANTILE`、`TS_ARGMAX/MIN`、`SIGN`、比较与 `SELECT`；风格中性化作为有独立输入契约的变换。每项根据实际种子消费者引入。EMA、复杂回归和高阶矩后置，避免为了对齐 105 项清单扩大首期范围。

迁移期间保持旧 schema v2 可复算。新增字段/行为进入显式版本化契约，由 validator 分派；不能把旧运行按新算子默认值重新解释。

### 5.1 五类变换

| 变换 | 示例 | 需要回答的问题 |
|---|---|---|
| 窗口变体 | 反转 5/10/20 日 | 信号持续期是否稳定，有无单一参数尖峰？ |
| 历史聚合 | 原值、历史均值、线性衰减、变化量 | 持续性与突发性哪一种承载信息？ |
| 同类输入替换 | 成交量异常与成交额异常 | 假设依赖交易股数还是资金规模？ |
| 控制暴露 | 行业中性、行业+规模、预登记的 CNE6 风格集合 | 信号是否只是已知暴露的替代表达？ |
| 有限交互 | 反转 × 成交量异常；盈利改善 × 估值 | 第二个条件是否改变原假设的适用范围？ |

先实现确定性规则，后续再考虑语法约束下的搜索。Agent 提交假设、父因子、允许变换和证据引用；执行器生成合法 JSON DAG，不接受自由 Python/C++/SQL。

### 5.2 一个可实现的首期家族

研究假设：“成交量异常时，短期下跌的后续修复表现是否不同？”

```text
reversal(w) = -(close / delay(close, w) - 1)
volume_surprise(v) = volume / sma(volume, v)
candidate = zscore(reversal(w)) * zscore(log(volume_surprise(v)))
```

定义 `w ∈ {5,10,20}`、`v ∈ {10,20}`、后处理 `{无中性化, 行业中性化}`，得到 **12 个交互候选**。3 个基础反转和 2 个量能信号作为对照，共 17 个表达式；若基础对照也增加变换，必须加入完整注册清单。

保留“原始”“中性化”版本，行业信息不合格时中性化版本 blocked。这个例子是待检验假设，没有预设盈利结论。原生价格契约仍要求明确的无公司行动范围；真实长期研究先完成公司行动与价格口径升级。

方向反转、市场状态切片和 horizon 也可能构成额外试验，需登记，不能在看到 OOS 后选最漂亮的解释。分类排序的 rank/标准化变体可能保持同一排序，应作为近似重复候选识别；它们仍可能影响线性模型的幅度，不简单删除。

### 5.3 分层筛选

1. **静态检查**：类型、单位、因果时间、可用字段、节点数、窗口和候选预算。
2. **结构去重**：规范 DAG hash；保留多父血缘与 alias。可安全交换的二元算子可规范化，不能随意结合/分配浮点运算，也不能简化改变 NaN 行为的表达式。
3. **输入质量检查**：缺失、常数、有效样本、异常值、warm-up；状态与排除原因进入台账。
4. **训练期相似性**：逐日截面 Pearson/Spearman、因子收益相关、与父因子的增量。使用绝对相关查正负重复，保留符号信息；共同样本不足则不可判断。
5. **验证期选择**：看净增量、稳定性、复杂度和交易代价。按冻结规则选代表，保存所有失败与淘汰结果。
6. **锁定候选后 OOS**：同一数据、模型和成本规则下比较基线与候选，测试结果不再用于本批修改。

建议工程试点每个 family 首轮 12–32 个候选，单研究批次最多 128 个已登记提案，进入单个模型最多 32 个因子；这些是资源与试验预算建议，不是统计显著性阈值。现有 200 万因子单元上限可能更早触发，必须预估实际尺寸。

同一批次分块执行仍共享预算、候选身份和测试窗记录；不能靠分 case/分 job 逃避试验计数。首期的因子评估动作应能独立运行，不要求每个被静态筛掉的候选都做完整模型与回测。

## 6. 归因拆成四个明确的产品能力

| 能力 | 问题 | 主要输出 |
|---|---|---|
| 结构解释 | 因子怎么算出来？ | DAG、输入、窗口、算子、中间值、版本和父子差异 |
| 因子风格解释 | 因子的截面差异被什么解释？ | 行业/规模/风格投影、解释度、残差与残差 IC |
| 模型预测解释 | 模型为什么给出这个预测？ | 线性贡献或分组置换/消融、fold、基准预测 |
| 组合收益与风险归因 | 实际赚亏和承担风险来自哪里？ | 风格收益、选股特异项、行业配置、成本/成交、风险贡献 |

四类结果用不同 schema 和单位。不得将结构复杂度、系数大小、SHAP 或风险贡献直接表述为已实现收益贡献，也不把回归解释当作经济因果证明。

### 6.1 结构解释先落地

从 factor registry 自动生成因子卡：

- 经济假设、适用场景和证伪条件；
- 公式与计算图，输入观察和最晚可得时间；
- 来源、算子版本、父因子及本次变更；
- 缺失原因、样本覆盖、复杂度与成本估算；
- 基于 train/validation 的家族比较，OOS 结果单独展示。

查看历史某日某股可以逐节点追溯，但所有大面板经注册 artifact 分页读取。自由文本解释只消费确定性结果，不自行推断某个节点贡献了多少收益。

### 6.2 因子风格解释

对某个因子截面 `z_t`，用截止时点合法的控制暴露 `X_t` 做显式加权投影：

```text
z_t = X_t β_t + e_t
```

控制集合可包括 country、历史行业、log 市值和批准的 CNE6 风格。行业与截距的共线性通过明确约束或基准组处理；报告样本数、有效秩、条件数、权重规则、R²/调整后 R²、系数和残差 coverage。共线控制组优先按组报告，避免给高度不稳定的单列贡献排名。

用 `e_t` 和原始 `z_t` 分别计算未来收益的 IC、分组及衰减，回答“控制已知暴露后是否仍有关联”。另行检验 `IC(z_t, u_{t+1})` 时，`u` 必须来自同口径的事后股票特异收益，明确与“残差化因子”的区别。

当天仅用合法 X/z 的截面中性化可以用于当天信号，不能使用当天之后才估计出来的 factor return。若 β、特征选择或预处理从多个日期拟合，必须限定训练窗并冻结应用。事后解释允许使用随后成熟的收益，但结果标签不能反流到当时决策。

残差并不自动成为纯 alpha。有限控制集合、误差和遗漏变量都可能留在残差中；结论应是“相对指定模型的未解释部分”。

### 6.3 模型预测解释

**Ridge 首先做**：现有 fold 已保存 clipping、scaler、系数和截距。对实际预处理后的特征：

```text
prediction = intercept + Σ(coef_j × transformed_feature_j)
```

逐预测验证加和与模型输出一致，记录收益单位/horizon。比较不同量纲或 fold 时不能直接比较未标准化系数。

**HGB 随后做**：优先采用按因子家族/相关簇的样本外置换，以及移除一组后重新训练的消融。置换规则保留需要控制的日期/行业结构和时间相关，不跨日期随意打乱全部单元。高度相关特征的单列重要度不稳定，应报告组级结果和不确定性。SHAP 作为后续可选解释工具。

增量验证至少比较：基线、基线+候选、移除候选组；每个方案预登记并以相同 folds、成本、账户规则重跑。单因子 IC 强而组合增量弱，可能是重复信息、容量或成本问题，需要由结果区分。

### 6.4 收益与风险归因

**CNE6 收益归因**使用期初合法暴露和对应持有区间事后估计的收益：

```text
r_i,t = Σ_k X_i,k,t-1 × f_k,t + u_i,t
C_k,t = Σ_i (wP_i,t-1 - wB_i,t-1) × X_i,k,t-1 × f_k,t
C_specific,t = Σ_i (wP_i,t-1 - wB_i,t-1) × u_i,t
```

country、industry、style、specific 分列。CNE6 的风险快照含暴露和协方差，并不自动提供可用于收益归因的每日 f/u 历史；新增 `FactorReturnSnapshot`，保存回归样本、暴露 vintage、收益定义、回归/发布时间、约束、拟合质量和源 hash。

若现有 CNE6 的收益序列是 close-to-close，首先以相同口径解释期初静态持仓，日内成交另外解释；不能将其直接套在 open-to-open 预测标签上。需做不同区间归因时重新定义并核验对应模型收益。

**Brinson 作为另一视角**，对期初权重与一致的组收益采用明确版本，例如 Brinson–Fachler：

```text
配置 A_g = (wP_g - wB_g) × (rB_g - rB)
选择 S_g = wB_g × (rP_g - rB_g)
交互 I_g = (wP_g - wB_g) × (rP_g - rB_g)
```

该公式要求权重、现金处理、组覆盖和基准收益定义一致；零权重/空组必须有显式约定，不用缺失收益补零制造选择能力。先对股票袖套/可复制基准核对，再桥接账户与实际指数。

Brinson 与 CNE6 是同一收益的不同解释，不能把两份贡献加在一起。前者适合回答行业配置/行业内选股，后者适合解释系统性风格收益与模型特异项。

**风险归因复用现有内核**：

```text
b = Xᵀw
σ² = bᵀFb + Σ_i w_i² d_i
因子方差贡献_k = b_k(Fb)_k
```

`d_i` 为特异方差。现有 `portfolio-risk` 已实现此类计算及个股风险贡献，不再另写一套不同公式。主动风险用 `wP-wB`，绝对风险用 `wP`；风险贡献可能为负，表示对冲，不能为了图表好看裁为零。组合研究持仓、现金及覆盖分母需通过适配契约接入，不能套用“股票权重必为 1”的输入假设。

## 7. 收益归因必须由账本独立核对

建议把目前的总差额残差拆成独立可计算项：

| 分量 | 独立依据 |
|---|---|
| 期初持仓收益 | 期初实际数量、前收/当日估值、已支持公司行动 |
| country/industry/style/specific | 对同一证券收益区间的暴露与回归 f/u |
| 成交时点效应 | 每笔真实成交数量、成交价、期末估值，与期初静态持仓对照 |
| 费用 | 唯一执行账本里的佣金、印花税、过户费 |
| 现金/应收 | 实际现金、利息、股息应收的确认和到账，避免重复确认股息 |
| 基准复制差异 | 期初指数成分收益重建值减真实指数收益 |
| 未解释核对误差 | 实际账户收益减上述独立分量；超容差使结果 partial/failed |

无公司行动、无外部资金流的简单验算：

```text
毛损益 = Σ q_begin × (P_end - P_begin)
       + Σ signed_fill_quantity × (P_end - P_fill)
净损益 = 毛损益 - 实际费用
```

股票分红、拆并股、应收及其他事件在该恒等式上按现有账本规则扩展；外部入出金需单独定义收益分母和时间加权方式。滑点已经体现在 `P_fill`，若展示滑点分项，要从成交时点项中重分类，不能再次扣减。

主动收益也要冻结现金口径。例如用 `Σ(wP-wB)r_i` 时，现金导致的少配股票影响已部分体现在主动权重里；直接再扣 `cashWeight × benchmarkReturn` 会重复计量。若产品展示“现金拖累”，应给出明确的中心化/重分类公式，并保持总额不变。

保留小的 `reconciliationError` 供核验，但不能把它全部命名为交易时点贡献。单日分解通过后，再用显式版本的多期连接方法（如 Carino）连接到累计主动收益，不能直接相加日贡献。对零超额、相同组合/基准收益采用连续极限，对不满足对数定义域的收益明确拒绝。

## 8. 评估治理：裂变越多，越需要控制试验

### 8.1 样本职责

- **Train**：拟合裁剪/标准化、跨日中性化参数、模型权重、因子相关簇。
- **Validation**：比较窗口、变换和家族代表，确定最终参数/候选。
- **Locked test**：只评估冻结方案。结果一旦被使用，该历史区间不能继续作为本批未见测试。
- **Forward observation**：按真实时间新增数据，用冻结方案观察稳定性。

按交易日历及实际标签区间做 purge/embargo，训练标签必须成熟且已公开。标签 horizon>1 时，收益和 IC 可能序列相关，应使用登记的 HAC 或时间块 bootstrap，不把重叠标签当独立样本计算显著性。

### 8.2 跨候选共享测试窗状态

在 ResearchWorkspace 的持久层增加规范 `TestPartition` 和 append-only 使用事件。逻辑身份包含市场、证券范围、标签定义、观察区间/来源血缘；除精确 hash 外，检测相同底层收益观察的区间重叠。更换 case、数据快照 ID 或因子版本不能重置已见状态。

状态建议为 `unseen → reserved → consumed`，消费前原子预约并记录注册引用；崩溃恢复检查同一请求。若已计算或持久化测试统计，不能因为流程报错把它退回 unseen。并发保证落在 workspace 级协调，现有 case 级锁不足以覆盖跨 case 竞争。

索引只负责检索。测试窗使用事件是权威研究数据，丢失索引后也不能丢失 consumed 状态。跨 workspace 是否允许共用测试域由显式研究权限决定；相同受控研究域内必须防止通过创建新 workspace 清空使用历史。

### 8.3 筛选指标与报告

每个候选至少记录：

- 数据可用率、有效证券日、排除原因、常数率与极值；
- 分 horizon 的逐日 IC/RankIC、衰减、分组收益与单调性；
- 年份/市场状态/行业/规模分层结果及样本量；
- 原始与中性化表现、与父因子/因子池代表的相关性；
- 同一账本下的净收益增量、换手、费用、拒单、容量和风险变化；
- 所属批次的完整候选数、实际尝试数和选择轨迹。

不设一个通吃所有 universe/horizon 的 `IC > 0.02` 或 `Sharpe > 1` 准入条件。阈值、主要检验和经济最低改进应事前声明。多重检验可按家族做层级控制，使用与相关结构相容的 FDR 或块重采样方法；不能未经论证把所有候选 p 值当独立。修正显著性仍不能替代一次真实未见测试。

负对照包括延迟数据、未来输入扰动、随机/打乱因子、遮蔽研究特征、单一风格代理。打乱方案须明确保留/破坏了什么结构；失败的负对照先触发泄漏检查。

## 9. 数据基础与规模化

A2 文档记录 24 只样本无法识别完整 CNE6 截面，2,597 个评估日均 rank-deficient。这个结论不能通过给新归因器输入相同小样本改变。**风险模型估计 universe 与策略持仓 universe 分离**：在足够宽且合格的历史截面估计模型，再给较小研究组合提供暴露/风险/收益引用。

建设分三条数据层次：

1. 合成/冻结 fixture：验证公式、时间隔离、谱系、归因与恢复；始终 synthetic，不能支持投资结论。
2. 限定用途真实研究切片：明确 universe、时间、来源和具体缺口；仅对已验收输入产生相应诊断。不能缩短原定验收窗或删除问题证券后宣称 A2 通过。
3. 经批准的全市场历史与增量发布：支持完整因子筛选、CNE6 和策略准入，继续受 A2/A4 门禁约束。

真实长期因子研究还需要解决：

- 公司行动、成交原价与研究收益价分离；避免将今天复权后的历史序列无条件用于历史决策。
- 财报首次版本、修订版本、TTM/MRQ 重构和披露精度；date-only 用显式可见区间规则，不能补造午夜时间戳。
- 历史证券主表、退市/停牌、行业与基准成分 vintage。
- 真实指数 price/total-return 类型、基准复制路径和发布日期。

性能按测量推进：现有上限是 500 证券、20 万 bars、32 因子、每图 64 节点、200 万因子单元，计算子进程超时 120 秒。即使只有 500 证券，20 万 bars 也不足以支持多年密集面板；不能只提高 factorCount。

后续优化顺序：

1. 规范 DAG 与安全的公共子表达式复用；
2. 缓存键绑定表达式、输入分区 hash、PIT cut、universe、算子/环境版本；
3. 日期分区携带必要历史 overlap；截面算子在同一完整截面计算，不能证券分块后各自 rank；
4. 资源预算、进度、取消、checkpoint、失败分区恢复；
5. 有实测瓶颈后评估向量化或编译执行后端，使用同一契约与数值/PIT 对照。

异步任务仍由现有研究应用层和 workspace 管理；无需先搭建独立量化平台。新增受信任执行后端也不应把源码、动态库或编译参数开放给 Agent。

## 10. 与 NGFI 主观研究能力结合

LocalQuant 的现有数据库主要组织量价表达式。NGFI 的差异化可以来自可审计的公司研究特征：

- 经营改善：利润率、订单、现金转化与资本开支假设；
- 预期变化：在来源与历史观察合格后衡量指引/一致预期变化；
- 证据强度：一手披露、独立证据、反证、资料新鲜度；
- 论点风险：主要假设被证伪的数量与严重程度。

这些变量应先成为版本化 `ResearchFeatureSnapshot`，记录证据、rubric、模型/提示版本、asOf、缺失和置信度；验证抽取准确性、稳定性及 PIT 后才进入因子图。`confidence` 是测量质量，不可默认映射成预期收益。

后续可以检验“盈利质量 × 估值”“经营改善 × 价格未反映”“论点恶化 × 高估值”等家族，但应同时设置传统量价/基本面基线及研究特征遮蔽对照。这样能判断 NGFI 的研究环节到底增加了什么信息，而非只让 Agent 给常见技术因子起新名字。

## 11. 实施落点与受控接口

保持既有 package 边界，以下为建议落点：

| 落点 | 建设职责 |
|---|---|
| `combinatorial-optimization/ngfi_quant/factors/` | registry、DAG 规范化、裂变规则、质量/增量诊断、风格投影 |
| `ngfi_quant/research_contracts.py` | 版本化因子、评估、生成和归因输入契约 |
| `ngfi_quant/research_models.py` | Ridge 贡献、模型组级诊断 |
| `ngfi_quant/portfolio.py` 及新增归因纯函数模块 | 独立收益分解、多期连接，使用唯一账户/成交内核 |
| `cne6_engine/interfaces/` | 历史 factor-return/specific-return 及暴露来源契约 |
| `portfolio-risk` | 复用风险贡献，增加研究账户/主动权重的明确适配 |
| `research-workflow` | 生成前登记、分阶段运行、候选比较、恢复与准入状态 |
| `research-workspace` | 因子版本/血缘产物、共享测试窗事件、可重建索引 |
| `dsh-finance-tools`、CLI、strategy preset | 同一服务入口、结果分页、方法解释 |

建议扩展现有 `finance_quant_research` 的闭合 action，而非按算子新增工具：

- `factor-catalog`：按类别、输入、算子、家族检索；
- `factor-register`：登记合法定义与假设；
- `factor-derive`：在注册预算内生成候选；
- `factor-evaluate`：执行独立因子评估；
- `factor-explain`：查询结构及已登记诊断；
- `factor-compare`：比较同一注册下的候选；
- `attribute`：对已登记模型/回放执行指定类型归因。

上述 action 已接入；另有 `factor-get` 查询不可变因子产物。`factor-catalog` 当前返回有界完整目录，`factor-explain` 执行预登记的开发窗风格诊断，结构解释由因子卡提供；`attribute` 只查询已保存的模型/收益/风险归因。所有写操作绑定 workspace/case/revision；计算动作先生成不可变注册，查询只接受 ID 和有界分页。继续沿用 Agent 8 MiB、单 artifact 128 MiB 等独立边界；实际参数见 [接口文档](quant-research.md)。

首期通过现有 DSH Web/headless 和 Markdown/结构化产物交付因子卡、家族比较、归因摘要。待真实研究任务证明需要，再建设专门的研究审阅界面。

## 12. 分阶段工作包与验收

| 阶段 | 主要交付 | 退出条件 |
|---|---|---|
| F0 契约与口径 | 四类解释定义、算子身份、因子版本、样本职责、旧新 schema 策略 | 固定现有输出基线；同名指标差异有明确映射，旧 run 可复算 |
| F1 因子资产 | registry、规范 DAG、血缘、反向依赖、因子卡 | 现有 12 模板纳管；改名不改表达式身份，改变参数/算子语义产生新身份；索引可重建 |
| F2 评估治理 | 独立因子评估、共享测试窗台账、注册与恢复、训练期去重 | 同一试验可复算；跨 case/并发/失败不能重置测试窗；无效数据保持明确状态 |
| F3 归因闭环 | Ridge 解释、因子风格投影、实际基准接线、CNE6/Brinson 与账本核对 | 已知真值 fixture 和独立公式一致；country、复制差异、费用、成交等可追溯；输入不足 blocked |
| F4 有界裂变 | 五类变换中的首批规则、候选清单、家族对照 | 先跑一个 17 表达式试点；候选数/成本/筛选完整留痕；未消费测试结果调参 |
| F5 数据与增量证明 | 合格真实 universe、成本/容量检验、前向观察、研究特征对照 | 在批准的数据用途内报告真实样本外增量；A2/A4 必要门禁通过后才讨论晋级 |
| F6 按需规模化 | 分区执行、缓存、checkpoint、性能与可选后端 | 按实际目标规模验收内存/耗时/恢复与截面一致性，不能只修改上限 |

F0–F4 的工程和合成验收可以推进；真实 CNE6 收益归因验收和 F5 受数据依赖约束。F6 可为 F5 所需规模提供专项支持，但不改变数据质量结论。实施按主要工作包逐项收口。

关键验收场景：

- 未来数据/行业/风险 vintage 扰动不改变过去合法信号与决策。
- 数值 fixture 覆盖并列 rank、常数、缺失、除零、滚动边界、`ddof` 和中性化秩不足。
- 结构相同但展示名称不同可识别；相同算子集合、不同字段/顺序不得误判完全重复。
- 已知“纯行业暴露”的合成因子被风格解释识别；控制后无信号时不能输出有效 alpha。
- Ridge 各项贡献与实际预测核对；HGB 的重要度不伪称可加和收益。
- 纯风格收益、纯特异收益、仅现金、仅费用、开盘成交、跳空、停牌拒单、分红应收、基准复制差异分别可辨认。
- 同组合与基准、零收益、长短贡献抵消、多期复利等边界核对。
- 请求量由决策固定，开盘跳空不重算委托；硬约束不可行不放松；既有 A3 回归继续通过。
- 所有候选/失败/重试可追溯；篡改 artifact、并发消费测试窗、索引重建均不绕过身份约束。

每阶段分别报告：工程是否完成、数据用途是否合格、策略证据是否充分。不能用测试数量、因子数量或合成收益替代后两项。

## 13. 建议的第一个可交付版本

定义为“**一个因子家族从登记到解释与评估的可复算闭环**”：

1. 将已有 12 模板和 17 算子纳入版本化目录，能查公式、输入、依赖和血缘。
2. 做通用评估注册与测试窗治理，提供因子卡和父子比较。
3. 支持 Ridge 精确预测分解；用合格/合成暴露验证风格投影及账本归因。
4. 对上述反转 × 量能家族生成 12 候选与 5 对照，先完成工程验收。
5. 输出每个候选保留/淘汰/阻断的理由，并保持真实数据归因缺口显式可见。

版本完成的价值是：用户可以知道一个候选如何产生、凭什么进入下一阶段、是否提供新信息、实际收益由什么解释。后续扩大算子库、引入更多研究特征和加速执行都有清晰接入点。
