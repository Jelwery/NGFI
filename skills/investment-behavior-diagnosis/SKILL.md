# 投资行为诊断

把用户的投资问题当成一个需要证据区分的决策过程，而不是一场“找偏差”游戏。行为金融机制是候选解释；一次交易、一段价格路径或一种情绪通常不足以确认稳定偏差。

## 先识别用户真正要解决的任务

按任务目标选择最短充分路径。真实请求可以同时包含多类任务，不要强迫它落入单一类别。

- 决策复盘：检查参考点、概率判断、规则一致性和可替代解释。
- 长期模式审计：需要多次可比较的决策或交易记录，先判断数据能支持什么。
- 市场状态解释：分开陈述市场事实、可能机制与不可识别的心理状态。
- 理论解释：直接回答概念、公式、证据和边界，不诊断提问者。
- 流程设计：针对已经有初步证据的机制设计可执行、可撤销、可验证的干预。

若用户只要求价格、收益、回撤、财务或估值，并明确不要行为分析，不加载本 skill；可直接调用合适的金融工具。

## 诊断协议

### 1. 明确决策与时间点

先确认用户在决定什么、何时需要决定、可选行动是什么。把以下内容分开：

- 已发生的事实：用户原话、交易记录、当时可见的信息；
- 当前观察：现时价格、市场数据或后来发生的结果；
- 用户解释：为什么买、卖、持有或改变计划；
- 分析推断：行为机制、竞争解释及置信度。

避免事后信息污染事前决策评价。结果好不等于过程好，结果差也不自动证明存在偏差。

### 2. 收集最少必要证据

只询问能区分解释的问题。优先补齐：

- 原计划、期限、仓位或风险预算，以及事前退出/加仓条件；
- 当时的参考点和备选方案，而不只问当前盈亏；
- 决策前可见的新信息，以及它如何改变概率或价值判断；
- 流动性、税务、集中度、负债、现金需求、交易成本和约束；
- 若声称“我总是这样”，需要多次可比较记录，而非印象总结。

信息不足时不必停止回答。给出暂定假设、明确缺口，再问 1–3 个最能改变判断的问题。
当用户要求从单次交易判断偏差时，要让“不足以判断”仍然可操作：至少核对事前计划/理由、基本面或信息变化、期限、流动性或现金需求、税务，以及集中度或风险预算；这些合理约束可能足以解释交易，不应被遗漏。

### 3. 建立候选机制，而非贴标签

每个重要判断使用同一个最小诊断单元：

1. 观察证据：用户说了什么，或工具实际返回了什么。
2. 候选机制：哪种偏好、信念或市场机制可能产生该现象。
3. 竞争解释：哪些理性约束、信息变化或其他机制也能解释它。
4. 缺失证据：什么信息能区分这些解释。
5. 当前置信度：低、中、高；高置信度需要重复、可比较且与替代解释有区分力的证据。
6. 流程干预：改变决策流程，而不是替用户决定交易。
7. 验证指标：事后用什么观察判断干预是否有效。

不要为了凑数量列出偏差清单。通常选择 1–3 个最有区分力的机制深入解释。

### 4. 按需加载理论

当前 DSH 不会自动读取 references。需要下列深度时，调用 `finance_behavior_reference`，topic 只能选固定值：

- preference-and-choice：参考依赖、CPT、概率加权、心理账户、处置效应、短视损失厌恶、路径依赖与时间不一致。
- belief-and-learning：贝叶斯基准、代表性、基率忽视、确认偏误、保守性、过度自信、自我归因、注意力和叙事。
- market-aggregation：有效市场基准、有限套利、看法差异、卖空约束、动量/反转、泡沫与市场周期。
- diagnosis-and-evidence：证据层级、置信度、市场证据与交易审计的解释边界、PGR/PLR 要求。
- interventions-and-boundaries：条件化干预、验证指标、投资建议/心理健康/隐私边界。

简单情境不必读取全部 reference。需要精确理论、公式、研究参数、长期模式审计或复杂市场机制时再读取对应文件。若工具失败，明确说未能读取，不声称依据了该文件。

### 5. 按证据需要选择工具

工具是可选证据，不是仪式。不要为了展示能力而取数。

| 需要回答的问题 | 首选方式 | 解释限制 |
|---|---|---|
| 用户当时为何决策、参考点是什么 | 对话中的事实与追问 | 自述也可能受事后合理化影响 |
| 近期价格路径、回撤、波动、基准差异 | finance_behavior_market_evidence | 市场统计不能证明个人偏差、羊群、FOMO 或泡沫 |
| 多笔交易的持有期、盈亏与规则执行 | finance_behavior_trade_audit | 描述模式不等于心理成因；不完整样本可能有选择偏差 |
| 公司基本面或分析师预期是否变化 | 现有 finance_fundamentals / finance_estimates 等 | 报告期、当前观察和预测必须区分 |
| 当前新闻、政策、叙事传播 | 仅在环境真实提供 web_search / web_fetch 时使用 | 未实际读取的网页不得引用；不可用时直接说明 |

市场问题先确定分析对象。用户说“某类股票”但没有定义成分时，不自行挑选一篮子股票并把它当成该类别；先说明范围不明确，必要时只用 1–2 个明确标为示例或代理的对象。默认先用一个最能回答问题的窗口；只有跨期限比较确实能区分解释时才增加窗口。

市场机制的竞争集合至少考虑：基本面或预期更新、贴现率/风险偏好、注意力/叙事/趋势外推、看法分歧与套利约束，以及机械资金流。只展开与现有证据相关的部分，不把这份集合变成固定长清单。

finance_behavior_market_evidence 使用 20、60、120 或 252 个交易日窗口，可选 benchmark。引用结果时保留 observation、status、单位、来源和 caveat。provider 失败或字段缺失时不补造数据。输出市场证据时至少明确：总体 status、观察/获取时间、provider/source、主指标单位，以及重要的 missing/partial 字段或 limitations；不要只摘出 available 数值而静默丢掉缺失状态。

finance_behavior_trade_audit 只处理用户明确提供的规范化记录，不访问账户、不保存数据。只有记录包含每个卖出日的已实现与账面盈利/亏损机会集时，才可计算 Odean 定义的 PGR/PLR；仅有已平仓交易时明确标记不可计算。引用审计结果时至少报告样本量、sample.startAt/endAt、盈亏组持有期、关键字段完整度和不可识别项；这些是判断纵向模式能否成立的边界，不是可省略的工具细节。

### 6. 把干预写成可检验流程

干预应针对已经提出的机制，并说明：

- 触发条件：何时执行；
- 具体步骤：用户实际要做或记录什么；
- 适用前提与副作用：在什么情况下不应机械执行；
- 撤销条件：何时停止或修改规则；
- 验证指标：规则遵守率、计划外交易次数、预测校准、持有期差异、决策后悔频率等。

优先采用决策日记、事前证伪条件、冷静期、检查清单、信息源对称、固定复核窗口和预承诺等流程工具。止损、分批卖出、降低看盘频率或固定仓位都不是普适最优答案；只有与用户期限、流动性和风险约束一致时才可作为选项。

## 置信度规则

- 低：只有单次行为、结果或模糊自述；存在多个同样合理的解释。
- 中：同一机制在多个相似决策中重复出现，且有部分事前记录或可比较证据。
- 高：跨情境稳定复现，有事前规则/预测与结果记录，关键竞争解释已被检验。高置信度仍不是临床诊断。

使用“与……一致”“提示可能存在”“当前证据更支持”等措辞。避免“你就是”“这证明了”“市场一定处于”。

## 特别边界

- 价格上涨、成交活跃、媒体热度或高估值都不能单独证明泡沫、羊群、FOMO 或某个投资者的偏差。
- 经典研究参数是特定模型、样本与估计方法下的结果。例如损失厌恶参数常见经典估计约为 2.25，但不能当作用户的固定心理系数。
- 处置效应是相对持有机会集的实现倾向，不等于“某笔亏损交易卖得慢”或“平均亏损持有期较长”。
- 不把行为机制写成临床心理或精神健康诊断。若用户表达失控、无法睡眠、借贷加杠杆或自伤风险，先建议暂停不可逆操作并寻求可信任的人或专业支持。
- 不要求账户凭证、身份证、券商登录信息或不必要的逐笔隐私数据。
- 不保证收益，不用行为诊断包装具体买卖、仓位或杠杆指令。

## 输出方式

按问题复杂度裁剪，不强制固定长报告。常用结构是：

1. 当前判断：1–3 个最值得检验的机制与置信度。
2. 证据与竞争解释：哪些事实支持，哪些替代解释也成立，还缺什么。
3. 理论解释：准确机制加一句通俗解释；需要深度时引用已读取 reference。
4. 流程干预：具体动作、适用条件、撤销条件和验证指标。
5. 若涉及市场：将事实、机制解释和不能下的结论分开。

理论问题直接给定义、机制、公式/证据边界和例子。市场问题先列事实再讨论多种机制。长期审计先报告样本与可识别范围，再谈候选模式。信息很少时，短答优于套用完整模板。
