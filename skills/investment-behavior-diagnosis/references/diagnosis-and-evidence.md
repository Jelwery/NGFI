# 诊断与证据：从观察到可检验假设

本文件用于复杂诊断、长期模式审计、数据工具解释和置信度校准。目标不是识别尽可能多的偏差，而是判断哪些机制真正有证据区分力。

## 1. 分析单位

每个机制使用七项记录：

| 项目 | 要回答的问题 |
|---|---|
| 观察证据 | 用户实际说了什么，工具实际返回了什么？ |
| 候选机制 | 哪个理论机制能产生这种现象？ |
| 竞争解释 | 哪些非偏差约束或其他机制也能产生它？ |
| 缺失证据 | 哪条新信息最能区分解释？ |
| 当前置信度 | 低、中、高，依据是什么？ |
| 流程干预 | 如何改变信息、环境或决策步骤？ |
| 验证指标 | 如何知道干预有效或应撤销？ |

这个结构可以内化，不必每次原样输出。简单问题应简短，复杂审计才需要完整表格。

## 2. 证据层级

从弱到强的大致顺序：

1. 单次结果：一笔盈利、亏损、买入或卖出。
2. 单次自述：用户对当时动机的回忆。
3. 多次结果：重复行为，但缺少事前理由和机会集。
4. 同类决策记录：含时间、备选项、规则、预测和当时信息。
5. 预注册式记录：事前写下概率、证伪条件、执行规则，并能与后续结果比较。
6. 跨情境重复与对照：机制在不同市场状态仍出现，竞争解释得到检验。

结果数据与心理机制之间通常存在识别缺口。同一行为可能来自偏差，也可能来自税务、流动性、策略约束、信息变化或合理风险管理。

## 3. 置信度校准

- 低置信度：只有一次行为或一段行情；候选解释多；关键信息缺失。
- 中置信度：多个可比较事件呈同向模式，部分事前信息可得，至少排除一项主要替代解释。
- 高置信度：跨时间或情境稳定，事前预测与规则完整，替代解释经过明确检验。

不要用“可能”“大概”掩盖武断结论。置信度应对应具体缺口，例如：“低，因为只有一次卖出且不知道事前规则、流动性需求和基本面变化。”

## 4. 避免结果偏误与后见之明

评价决策过程要使用决策当时可见的信息。后来上涨不证明卖出错误，后来下跌不证明卖出正确。检查：

- 事前概率是否合理，而非结果是否命中；
- 规则是否在结果揭晓前存在；
- 同一规则是否对正负结果一致执行；
- 新证据出现后是否按约定更新。

如果只能获得事后回忆，应标记记忆重构和自我辩护风险。

## 5. 市场证据工具的解释

finance_behavior_market_evidence 返回中性路径统计：观察窗口、有效样本、缺失比例、区间收益、最大回撤、实现波动率、相对 benchmark 收益、阶段高低点距离、多个窗口动量和成交量变化。

这些统计可以：

- 核实用户所称“最近大涨”“剧烈波动”是否与选定窗口一致；
- 区分绝对走势和相对基准走势；
- 确认决策是否发生在近期高点、回撤或高波动环境；
- 为后续追问提供时间锚点。

它们不能单独：

- 判断用户存在 FOMO、损失厌恶或代表性偏差；
- 证明交易者群体在羊群交易；
- 证明价格偏离基本价值或市场处于泡沫；
- 判断一笔买卖是否合理。

检查每项字段的 status。available 才可作为数值证据；missing、stale、provider-error 和 not-applicable 应原样披露。比较 benchmark 时要检查日期对齐和样本重叠。

## 6. 交易审计工具的解释

finance_behavior_trade_audit 接受规范化、已完成的交易或决策记录。适合分析：

- 样本量、覆盖时间与字段完整度；
- 盈利和亏损交易的持有期分布；
- 毛收益、净收益和费用拖累；
- 重复进出间隔；
- 事前理由、置信度和规则遵守记录的可用性。

审计结果是描述统计。常见限制包括：

- survivorship/selection：只有已平仓交易，未平仓亏损不在样本中；
- strategy mixing：长期持仓与短线交易不可直接比较；
- regime confounding：盈亏交易处于不同市场阶段；
- tax/liquidity：卖出原因可能是税务或现金需求；
- lot ambiguity：多次买入的成本匹配规则不明；
- missing opportunity set：不知道卖出日其他持仓的账面盈亏。

### PGR/PLR 的最低要求

Odean 式指标需要在每个卖出日识别：

~~~text
PGR = RG / (RG + PG)
PLR = RL / (RL + PL)
~~~

RG、RL 是已实现盈利/亏损机会；PG、PL 是同日未实现的账面盈利/亏损机会。只有 completed trades 无法提供 PG/PL，所以工具必须返回不可计算原因，模型不得从胜率或平均持有期伪造 PGR/PLR。

## 7. 竞争解释清单

按情境选择，不要机械罗列：

- 信息：基本面、政策、估值或风险认知真实变化；
- 约束：现金需求、保证金、集中度、授权范围、负债、期限；
- 摩擦：税务、手续费、冲击成本、借券、交易窗口；
- 策略：趋势、均值回复、再平衡、风险平价、对冲；
- 数据：样本选择、缺失、时间错位、回忆偏差；
- 行为：参考依赖、外推、确认偏误、注意力、过度自信、后悔规避；
- 市场：信息扩散、风险溢价、融资条件、有限套利、叙事传播。

竞争解释的价值在于提出区分测试。例如“如果这是税务损失实现，卖出应集中在税年末且可能换入相关资产；如果是恐慌，规则外卖出应与短期波动和情绪记录同步。”

## 8. 数据质量和时间纪律

每次数据性判断检查：

- provider 与 source；
- retrievedAt 与 observedAt；
- 窗口和有效观测数；
- 单位、币种、复权口径；
- 缺失比例和非同步交易日；
- 当前、历史、预测和模型假设是否混淆。

不要因为工具返回 JSON 就默认其正确。若数据明显异常、区间不足或 provider 报错，降低结论范围并报告限制。

## 9. 最少追问原则

优先问最能改变行动的问题，而不是搜集完整个人档案：

- “卖出条件是事前写下的，还是看到亏损后才决定的？”
- “若没有买入成本这个数字，你会用什么前瞻信息比较持有与现金？”
- “这四次盈利的事前概率和基准表现有记录吗？”
- “所谓最近上涨指 20、60 还是 252 个交易日，相对什么基准？”
- “这些记录是否包含未平仓头寸和每个卖出日的机会集？”

若答案不会改变机制排序或建议，就不要问。

## 10. 诊断审计清单

完成前检查：

- 是否把用户事实、工具数据和自己的推断分开？
- 是否至少给出一个有实质意义的替代解释？
- 是否说明什么证据会推翻当前判断？
- 是否把单次结果误写成稳定人格或模式？
- 是否把市场统计误写成心理证明？
- 是否隐藏了字段缺失、provider 失败或 reference 未读取？
- 干预是否有条件、指标和退出方式？
