三大投研 Skill 的价值与局限评估

评估对象：公司财务分析、宏观周期与政策分析、投资行为诊断。
评估视角：NGFI（Next Generation Finance Investment）——一个 AI-native 的投研与量化一体化系统。

判断依据：三份 SKILL.md 全文 + NGFI 目标架构中的「五接口、Signal 契约、点时纪律、确定性引擎 vs LLM 分工」。标注「成熟度」指工程结构与实现完整度，不等同于策略收益已被独立复现。

一、总览与结论

一句话：三个 Skill 的水平都远高于「AI 帮你炒股」的套路；其中「公司财务分析」几乎就是你想要的基本面路雏形。但它们目前都是「研究 / 方法资产」，而不是「信号 / 回测资产」。

Skill对应 NGFI 哪一路 / 哪一层对项目的帮助直接可用度
公司财务分析基本面路 + 研究准出 / 质量门控★★★★ 高（核心件）需改造后接入
宏观周期与政策分析市场状态路 + 事件 / 政策叙事★★★ 中高（上下文与门禁）不能当信号用
投资行为诊断与信号链路无关 → 用户体验 / 复盘★★ 中（产品差异化，非核心）定位需确认

核心判断：真正对 NGFI 核心（信号 / 回测 / 融合）有直接贡献的是「公司财务分析」；「宏观」是有价值的上下文与门禁材料；「投资行为诊断」是产品体验资产，与信号引擎无关。

二、这三份 Skill 是什么

三份 Skill 都位于 Claude Code 的 skills 目录，是面向「可移植投研方法」的自包含实现，每个都有自己的 SKILL.md、references/ 参考材料与 scripts/ 脚本。

Skill核心用途最有价值的机制
公司财务分析上市公司六阶段全面财务分析（初步→利润表→资产负债表→现金流→特殊指标→估值），产出研报级报告确定性计算脚本 + 致命信号体系 + 结构化状态契约
宏观周期与政策分析自上而下：周期定位 → 政策解读 → 资产含义三层框架 + 第 3 层的「双 Agent」防偏见流程
投资行为诊断用行为金融学分析用户决策：个体偏差 → 市场状态 → 行为模式三层检查项 + 行为改善工具箱 + 诊断必配行动

三、公司财务分析 —— 价值最高

它最打动人的一点：已经在实现 NGFI 的关键论点——「确定性引擎做计算、LLM 做解读」。

与 NGFI 理念的匹配度
NGFI 论点该 Skill 的实现判断
确定性引擎算数，LLM 解读calc_ratios.py / calc_risk_models.py / calc_valuation.py 做全部除法/指数计算；LLM 只写叙事；明令禁止心算高度契合
反幻觉 / 可审计「不编数据」「计算必须代码验证」「数据标注来源与可信度 L1/L2/L3」「交叉验证 4 必修项」正是审计基调
质量门禁 / quality_flags致命信号体系：M-Score、Z-Score、AG、存贷双高、大股东减持/质押、临阵换审计师等可直接映射
版本 / 可复现state.json、增量更新、metadata 键名规范、last_valuation.results 作为唯一对外接口符合版本追踪
结构化契约报告模板 + 固定 JSON 结构（pessimistic / neutral / optimistic / recommended）端到端契约干净

必须补的 4 个缺口

  1. 产出的是「当前时点」分析，不是点时历史。市值 / PE / 10Y 国债收益率 / 可比公司 PE 全部用 WebSearch 拉当下值。这满足"作为 of today 的研究"，但喂不进 NGFI 的 BacktestEngine 做 OOS——回测缺的不是"今天值多少钱"，而是"2023-06-01 那天当时知道什么"。这一点与 NGFI 的「禁未来函数 / 点时数据」是相反的运行逻辑。
  2. 产出是内在价值区间，不是带方向和强度的 Signal。它刻意「禁止出现股价、禁止算上行空间」——很好的研究纪律，但也意味着它不是 NGFI 的 direction / strength / probability / valid_until。需要一个「翻译层」把它包成 SignalPlugin 的候选（基本面假设），而不是直接当信号。
  3. 无概率校准、无 walk-forward、无回测。估值靠情景假设（scenario.json，rf / ke / peer_pe 手工定），正是 NGFI 文里说的「关键假设全部缺乏数据支撑」那类主观输入。它应当作为单路候选，由 FusionPolicy 去做校准和相关性惩罚，绝不能让它直接定买卖。
  4. 数据源裸用 akshare / 新浪 / 东财 + WebSearch。这正是 NGFI 警告的「来源漂移 + 合规」，且无缓存、无 DataProvider 抽象。接入时必须挪到统一 DataProvider 契约后面。

建议：把它的脚本 + 致命信号库 + 状态契约抽出来，作为 NGFI 基本面路的质量门控与研究方法基线；把 akshare / WebSearch 换成 DataProvider，把「当前时点分析」扩成「可按 as-of 回放」，并补一个到 SignalPlugin 的包壳。它 447 行里最值钱的是致命信号库和确定性计算纪律，不是抓取层。

四、宏观周期与政策分析 —— 好材料，但不能进融合打分

它最亮的设计是第 3 层的双 Agent 流程（Agent A 纯理论预测、看不到行业结论；Agent B 只拿 A 的输出推导行业方向、看不到原始数据）。这正好避开了 NGFI 反感的「数据→先下结论→再补理论包装」，和 NGFI「Agent 做解释/审计、不做最终裁决」高度一致，值得保留。

它对 NGFI 的帮助
机制对应 NGFI判断
周期定位（美林时钟 / 产出缺口）市场状态正是「市场状态路」与 market_regime 门禁角色
政策解读（降准 / 降息 / MLF / 美联储）事件 / 政策可作事件 / 政策叙事
受益 / 承压行业映射行业方向只作文本上下文，不能当信号

三个硬伤

  1. 全员定性、无确定性计算、无回测、无校准。它无法给出一个"可回放、可计分"的市场状态标签。在 NGFI 里，市场状态的判断应当是确定性的规则函数（像仓里的 market_regime.py），这个 Skill 只负责解释那一层。
  2. 宏观预测信噪比极低，且容易变成"事后合理"的叙事。若让它直接参与融合打分或作为证据，等于把低可验证性输入当成证据。必须严格门控为上下文 / 门禁，不参与 Signal 融合权重。
  3. 同样用 WebSearch 拉数据，不产出点时历史，无法用于 walk-forward 的状态历史标注。

建议：把它降格为 NGFI 的「市场状态 / 政策解释器」——给一个确定性 regime 规则（market_regime.py）做状态标签，这个 Skill 提供解释与叙事，以及给用户的「为什么」。它是好的解释层，但它不该成为信号源。

五、投资行为诊断 —— 与信号引擎无关，是产品/体验资产

必须诚实：它对 NGFI 的投研/量化核心几乎没有帮助——它不产生任何可回测、可融合、可验证的信号。它分析的是用户自己，不是标的。

但它的价值在产品层，而且不低：

  • 飞书 Bot 的「为什么 / 审计」、Web 的「复盘」环节，用行为金融做用户诊断与干预，是很好的差异化与留存点。
  • 三层框架 + 行为改善工具箱 + 禁止箭头链 + 「诊断必配行动」，写得专业且可执行。
  • 内容扎实（前景理论、处置效应、明斯基、卖空约束……）。

要留意两点

  1. 定位张力：NGFI 的核心卖点是「可验证信号」，行为诊断是「心理学辅导」。它更像一个伴生功能，放进 P1/P2 的产品闭环（Web 复盘 + Bot 交互）即可，别放进 P0 的信号引擎。
  2. 可验证性：诊断「用户偏差」本质是主观推断，无法回测/校准。好在它的措辞是「我注意到一个可能的模式」——这种探索语气是对的，别改成断言式。

建议：把它作为 NGFI 的用户侧行为引导 / 复盘助手，挂在 Bot 与 Web 的「复盘 / 为什么」入口，属于产品差异化资产，优先级放在 P1–P2。

六、三者共同的最大缺口

它们都不产出 NGFI 所要求的机器可消费 Signal 契约。

三个 Skill 输出的都是人类可读的研究 / 叙事 / 诊断；而 NGFI 要的是带 signal_id / version / as_of / horizon / direction / strength / probability+calibration / evidence_refs / valid_until / quality_flags 的结构化、带版本、可回放、经校准的信号，并且能回溯到点时数据、模型版本、回测口径（对应 NGFI 那张 Signal 字段表）。

最关键的一句话：这三个 Skill 是「方法与质量资产」，不是「信号与回测资产」。它们能帮你把「研究正确、结论可解释」做扎实（NGFI 首版目标），但要把它们变成「可回放、可融合」的竞争力，缺了一整个契约层——EvidencePack 契约 + DataProvider 抽象 + 点到 SignalPlugin 的翻译壳 + 确定性 vs LLM 的强制拆分。

好在——它们恰恰是 NGFI 文档里分配给 agent-agnostic-stock-skills / ai-berkshire 的那份「投研方法资产」的、更严格更自洽的现成版本。你可以拿这三个 Skill 作为 NGFI 研究方法链路的基线参考实现，再统一回收进五接口契约。

七、落地建议（按优先级）

优先级动作
P0（核心）从「公司财务分析」抽取确定性脚本 + 致命信号库 + state.json 契约，作为 NGFI 基本面路的质量门控与方法基线；把 akshare / WebSearch 挪进 DataProvider 抽象
P0（契约）定义一个 Skill → Signal 的翻译壳：只在「确定性数据 + 研究结论」齐备时，才把它升格为带 evidence_refs 的候选，避免直接把研究当信号
P1（门禁）「宏观」降格为市场状态 / 政策解释器：regime 标签交给确定性规则，这个 Skill 只做解释叙事
P2（体验）「投资行为诊断」挂在 Bot / Web 的复盘与「为什么」入口，作产品差异化，不进信号引擎
全程三点纪律对齐 NGFI：点时历史（当前是"当下分析"，要做 as-of 回放）、版本 / 可复现、来源漂移与合规（akshare / WebSearch 需纳入集中适配器治理）

八、总结

一句话结论

三个 Skill 的水平都远高于「AI 帮你炒股」的套路，尤其「公司财务分析」几乎就是你要的基本面路的雏形；但它们目前都是「研究 / 方法资产」而不是「信号 / 回测资产」。真正要喂进 NGFI 的核心，需要一层 EvidencePack + SignalPlugin 的契约包壳，并解决「点时历史」与「确定性 vs LLM 拆分」这两个关键缺口。

下一步最有价值的第一刀：按 NGFI 的五接口契约，把「公司财务分析」重构成一个带 EvidencePack 约束、可作 as-of 回放、能吐 quality_flags 的 SignalPlugin 样式原型。

本报告为静态审阅（基于 SKILL.md 全文与 NGFI 目标架构的对照），未做真实数据拉取、全量回测或生产压测。结论意在说明三者对 NGFI 的定位贡献与局限，不构成任何投资建议，亦不代表策略收益已被独立复现。
